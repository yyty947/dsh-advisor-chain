# Second Opinion（第二意见）

在需要时向配置好的顾问模型征求第二意见。与需要手动提供背景的方案不同，顾问通过 DSH 的会话投影（`deriveMessages()`）**自动看到当前会话的完整对话记录**——主模型调用时只需要一句问题。

## 它做什么

- **`second_opinion` 工具**：参数只有 `question`（必填）和 `context`（可选，仅放对话里看不到的信息，例如主模型的私有推理意图或未说出口的约束）。执行时插件自动把主会话的派生消息历史压缩成有界的文本抄本发给顾问。
- **顾问模型链**：设置里配置一个有序模型列表，前面的失败（请求出错、超时无产出）时自动顺延到下一个；超时但有部分产出时按「已截断」的成功结果接受并显式标记。
- **自动/手动两种触发**：
  - `auto`（默认）：系统提示注入一段简短的使用边界——重大方案决策前、高风险判断、低置信、连续受阻时主动咨询；
  - `manual`：只注入一句说明，仅当用户明确要求时才调用。
- **硬触发**：同一用户问题在会话中重复达到阈值（默认 3 次）时，提示升级为「本轮必须先咨询顾问再作答」。
- **会话卡片**：每次咨询以 `advisor/start`、`advisor/delta`、`advisor/message`、`advisor/end` 事件写入会话日志，聊天流中渲染成卡片——问题、顾问思考过程（默认折叠）、回答、截断标记与逐条尝试记录，重启后仍可回放。

## 设置

设置 → 插件 → Second Opinion（第二意见）：

| 配置 | 说明 |
|---|---|
| 启用开关 | 总开关 |
| 触发模式 | auto / manual |
| 顾问模型链 | 有序列表：显示名、provider（下拉）、模型 id（可点「获取模型列表」拉取）、推理档位、温度、maxTokens、超时 |
| 顾问系统提示词 | 整条链共用的人格与回答要求 |
| 重复提问阈值 | 硬触发的重复次数 |
| 抄本预算 | 发给顾问的对话抄本字符上限、单条消息上限、默认超时 |

配置保存后即时生效（volatile 配置，无需重启）。

## 已验证的行为

- 顾问调用复用 DSH 已配置的 provider 路由与凭据（`ctx.llm.stream`），插件自身不保管 API Key。
- 超时语义：流超时后静默停止，插件自行检测并标记 `truncated`，不会把半截回答当成完整结果。
- 顾问身份不递归：顾问是单次 `llm.stream` 纯文本调用，没有可用的子工具，天然不会衍生代理。

## 已知限制

- 顾问当前为纯文本问答（v2 计划：standalone 模式 + 只读工具 agent loop）。
- 顾问看到的是文本化抄本而非原始多模态消息；图片等内容以「非文本块」占位符呈现。
- 自定义会话事件类型通过对 `KNOWN_SESSION_EVENT_TYPES` 运行时集合的兼容性变更注册（与 dsh-advisor-group 相同的过渡方案）；DSH 提供官方注册面后会迁移。
- 与 dsh-advisor-group 同时启用时定位不同（本插件：单顾问第二意见 + 全上下文自动继承；advisor-group：多顾问接力会诊），工具名与提示段名已错开。
